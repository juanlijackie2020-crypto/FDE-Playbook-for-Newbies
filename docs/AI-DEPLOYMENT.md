# 可选 AI 服务部署

当前线上站点是 GitHub Pages 静态应用；`config.json` 的 `apiBase` 为空，真实 AI 未启用。其他模块和明确标注的规则演示可以正常使用。

## 服务与配置

仓库提供无第三方运行依赖的 `ai-service.mjs`，需要 Node.js 22+ 和一个支持 OpenAI-compatible Chat Completions / JSON mode 的模型服务。

服务端环境变量（使用托管平台的 Secret 管理，不提交到仓库）：

| 变量 | 用途 / 默认值 |
| --- | --- |
| `AI_API_KEY` | 模型密钥，必须，仅服务端读取 |
| `AI_MODEL` | 实际可用的模型 ID，必须，按服务商设置 |
| `AI_BASE_URL` | HTTPS API 根地址，默认 `https://api.openai.com/v1` |
| `ALLOWED_ORIGINS` | 允许的前端 Origin，逗号分隔，必须；不要带路径或通配符 |
| `AI_HOST` | 监听地址，默认 `127.0.0.1`；容器需要时设置 `0.0.0.0` |
| `AI_PORT` | 服务端口，默认 `8787` |
| `AI_REQUESTS_PER_MINUTE` | 单来源连接 IP 每分钟请求数，默认 10，最大 60 |
| `AI_DAILY_REQUEST_LIMIT` | 每进程 UTC 日请求上限，默认 200，最大 10000 |
| `AI_MAX_CONCURRENT` | 并发模型请求上限，默认 2，最大 10 |

示例配置值（不是密钥）：

```text
ALLOWED_ORIGINS=https://juanlijackie2020-crypto.github.io
AI_MODEL=<your-available-model-id>
AI_BASE_URL=https://api.openai.com/v1
```

本机开发时允许 Origin `http://127.0.0.1:4173`。不要在前端设置 API Key，也不要在命令行或聊天中打印真实密钥。

1. 在受信任的服务器/容器部署服务源码和 `content/`，配置上述服务端环境变量，执行 `npm run start:ai`。
2. 在 HTTPS 反向代理后暴露 `/api/health`、`/api/qa`、`/api/interview`。不要公开 `.env` 或完整仓库；只转发这些 API 路径。服务本身不提供 TLS。
3. 将公开 `config.json` 改为 `{"apiBase":"https://your-api.example/api"}`。这里仅有公开端点地址，没有密钥。
4. 浏览器必须能跨域访问配置的 Origin；服务对未批准的 Origin 返回 403。`health` 返回 `{configured:true/false}`，只说明必需配置存在，不能证明服务商额度或模型可用。
5. 重新发布 Pages。测试真实问答、源文链接、证据不足、客户多轮访谈及复盘。当前自动验收使用模拟响应，不能代替真实模型质量验证。

如果暂不启用，保持 `apiBase` 为空即可；没有必要为内容浏览引入会员、数据库或额外服务。

## 端点和数据边界

- `GET /api/health`：配置状态，不包含密钥、模型账户或配额细节。
- `POST /api/qa`：`{question, language: "zh"|"en"}`。只检索服务器 `content/knowledge.json` 的 published 章节正文，相关性排序选取最多 5 段；当前为轻量关键词检索，没有向量数据库。找不到依据不调用模型。模型引用必须指向真实文档与章节，且原文引句必须为该章节的精确子串；无引用时不展示为有据回答。引用存在不保证所有论述语义正确，仍需人工复核。回答与 AI 推断分开展示。
- `POST /api/interview`：`{action:"turn"|"feedback", scenarioId, practiceLanguage, language, messages}`。每次提交当前对话，不建立持久服务端会话。背景、语言、逐步透露信息与合理未知由系统提示限定。用户发言作为非可信数据；模型输出只按文本渲染，不执行 HTML 或工具操作。
- 反馈每一维度的 quote 必须来自用户实际发言；confirmed facts 必须来自客户实际回复，不能将未透露的背景当作用户应已掌握的事实。英文建议单独展示，不评价语言流利度为 FDE 能力。
- 本应用不在服务器记录提示词、对话正文或密钥；客户端对话仅存页面内存。模型供应商/托管平台自身日志与数据政策需要单独确认。用户提交前界面有发送到模型服务的提示。
- 私有 PDF、提取文本、笔记、题库不由前端发送到 AI。若将来扩展私有资料问答，需要显式的发送同意、文档权限模型和新的隐私评审；当前未实现。

## 限制、成本与上线前检查

- JSON 请求最大 40 KB；问题 1,000 字符；访谈每条用户输入 1,200 字符；每次最多 12 轮；输出 token 上限 2,200；模型超时 25 秒；前端超时 35 秒。
- 提供 IP 频率限制、每日总请求上限、全局并发上限、CORS Origin 检查、输出校验和不会泄露服务商错误详情的错误响应。
- 限流/每日计数只在单进程内存中，重启会清零，多副本不共享。默认不要通过多副本部署绕过总额度；规模扩大后需共享限流存储或网关。
- 不信任用户提供的 X-Forwarded-For；默认按 TCP 来源 IP 限制。反向代理后多个用户可能共享同一来源限制，这是保守限制。公网生产应在可信入口另设正确的客户端 IP 限流。
- Origin/CORS 不是身份认证，非浏览器客户端可以伪造 Origin。公开服务仍可能被滥用。用供应商账户预算、配额/消费告警及入口网关控制成本；需要时增加挑战或鉴权，而非只依赖前端按钮。
- 未承诺具体每次费用。成本取决于模型、上下文、输出和实际调用量；先用少量真实请求测量再设预算，保留快速禁用方法（停止服务或清空 apiBase）。
- 未配置返回 503；限流 429；不可信来源 403；无效输入 400/413；模型错误/不合格引用 502。前端保留失败时原输入，不默默切换为假 AI 回答。
